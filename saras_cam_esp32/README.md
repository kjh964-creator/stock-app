# Saras CAM v2 (ESP32-CAM 펌웨어)

AI-Thinker ESP32-CAM 보드용. 영상 스트림 + 사진 캡처 + 팬/틸트 서보 제어 + OTA.

## 요구사항
- Arduino IDE 보드: **AI Thinker ESP32-CAM**
- **ESP32 Arduino Core 3.x** (`ledcAttachChannel` / `ledcWrite(pin, duty)` 사용)
- 첫 업로드는 **USB 권장** (부팅 로그를 봐야 서보 진단이 됨). 이후는 OTA.

## 배선
| 용도 | 핀 | 비고 |
|---|---|---|
| 팬(좌우) 신호 | GPIO 13 | |
| 틸트(상하) 신호 | GPIO 15 | 안 되면 GPIO 14 로 변경 (`TILT_PIN`) |
| 서보 전원 | 별도 5V | 캠보드 5V 에서 따면 전류 부족으로 떨림 |
| GND | 공통 | 서보 GND ↔ 캠보드 GND 반드시 연결 |

**서보에 쓰면 안 되는 핀**: 0(XCLK), 4(플래시 LED), 16(PSRAM), 12(부팅 스트래핑 — 보드가 안 켜짐)

## 주소
| 주소 | 설명 |
|---|---|
| `/` | 점검 페이지 (폰에서 서보 직접 조작 가능) |
| `:81/stream` | MJPEG 실시간 영상 |
| `/capture` | JPEG 사진 한 장 (AI 자율주행용) |
| `/servo?pan=90&tilt=90` | 절대 각도 (pan 0~180, tilt 30~150) |
| `/servo?dp=10&dt=-10` | 상대 이동 |
| `/status` | 상태 JSON (서보 attach 여부, PSRAM, heap, RSSI) |
| `/servotest?ch=tilt` | 틸트만 단독 자동 스윕 — 상하 고장 진단 |

OTA: 호스트명 `saras-cam`, 비밀번호 `saras1234`

## v1 → v2 수정 내역
1. **스트림 헤더 버퍼 넘침** — `char hdr[80]` 에 87바이트 헤더를 만들고 `n=87` 로 전송해서
   버퍼 밖 7바이트를 내보냈음. `hdr[128]` + 길이 클램프로 수정. **스트림 끊김의 직접 원인.**
2. **`camera_config_t` 미초기화** — 스택 쓰레기값이 안 채운 필드에 들어감. `= {}` 로 0 초기화.
3. **카메라 동시접근** — `/capture` 와 `/stream` 이 프레임버퍼를 동시에 잡아 다툼.
   FreeRTOS 뮤텍스로 직렬화.
4. **PSRAM 없을 때 VGA 초기화 실패** — QVGA + DRAM 으로 자동 강등, 1회 재시도 추가.
5. 스트림 종료 시 마지막 chunk 전송(소켓 정리), `WiFi.setSleep(false)`,
   WiFi 무한대기 제거 + loop 재연결 감시, 확인 페이지 IP 하드코딩 제거
   (`location.hostname` 사용).
6. **`ledcAttach` 반환값 확인** — v1 은 버렸음. 이제 시리얼과 `/status` 로 성공/실패 보고.
7. `/status`, `/servotest` 추가.

`/servo` 응답 형식(`pan=90 tilt=90`, text/plain)은 v1 과 동일하게 유지 — 기존 조종 페이지 호환.

## 상하(틸트) 안 될 때 진단 순서

1. USB 연결 후 시리얼 모니터 **115200**. 부팅 로그에서 이 줄 확인:
   ```
   [서보] TILT pin=15 ch=1 attach=OK
   ```
   - `attach=FAIL` → LEDC 채널 충돌. `TILT_PIN` 을 14 로 바꿔 재업로드.
   - `attach=OK` → 소프트웨어 정상. 아래로 진행.

2. 폰/PC 브라우저에서 `http://<IP>/servotest?ch=tilt` 실행 (5도씩 자동 스윕).
   - **움직임** → 펌웨어 정상. 조종하는 쪽에서 보내는 명령 확인.
   - **안 움직임** → 신호선 배선 → 서보 5V → GND 공통 → 서보 고장 순서로 확인.
   - **떨리기만 함** → 5V 전류 부족. 전원 별도 공급.

3. 결정적 교차 테스트: **두 서보의 신호선을 서로 바꿔 끼운다.**
   - 문제 서보가 팬 핀(13)에서 잘 움직이면 → GPIO 15 또는 그 배선 문제
   - 바꿔도 안 움직이면 → 그 서보 자체 또는 기구부 걸림

4. SD 카드가 꽂혀 있으면 빼고 테스트. GPIO 13/15 는 SD 카드 신호선과 공유됨.

## 참고: tilt 범위 제한
`TILT_MIN 30` / `TILT_MAX 150` 으로 강제 클램프됩니다 (선 당김 방지).
`/servo?tilt=0` 이나 `?tilt=180` 을 보내면 30/150 으로 깎여서 "반응 없음"처럼 보일 수 있습니다.

## 접속이 안 될 때 (`http://172.30.1.41` 안 열림)

순서대로 확인:

1. **시리얼 모니터 115200** — 부팅 로그에 뭐가 찍히는지가 답입니다.
   - `[WiFi] 연결됨! IP -> 172.30.1.41` 이 나오나요?
   - 다른 IP 가 나왔다면 그 IP 로 접속하세요.
   - `[WiFi] 연결중....` 에서 멈춰 있으면 SSID/비밀번호 확인.
2. **폰이 같은 와이파이인가** — LTE/5G 로 잡혀 있으면 절대 안 열립니다. 가장 흔한 원인.
3. **PC 에서 `ping 172.30.1.41`** — 응답 있으면 보드는 정상, 폰 쪽 문제.
   응답 없으면 보드가 네트워크에 없음.
4. **정적 IP 충돌 배제** — `USE_STATIC_IP` 을 `0` 으로 바꿔 재업로드.
   공유기가 IP 를 주고 시리얼에 찍힙니다. 그 IP 로 접속.
5. **공유기 단말 간 차단(AP isolation)** — PC ping 은 되는데 폰만 안 되면 이것.
   KT 공유기 설정에서 "무선 단말 간 차단" 해제.
6. **전원** — USB 5V 가 약하면 WiFi 연결 시점에 브라운아웃 리셋이 반복됩니다.
   시리얼에 부팅 로그가 계속 처음부터 다시 찍히면 이 경우. 전원 교체.
